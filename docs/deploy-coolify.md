# Deploying OpenBot on Coolify v4

Deploy OpenBot on a single Linux VPS using Coolify's Docker Compose build pack. This guide covers
the complete stack including PostgreSQL, migrations, API server, web UI, and browser automation.

## Prerequisites

- Coolify v4 installed on your VPS
- At least 8 GB RAM (the stack uses ~3 GB, leaving room for other applications)
- A domain pointed at your Coolify instance
- A CopilotKit Intelligence account ([sign up free](https://intelligence.copilotkit.ai))

## Quick Start

1. In Coolify, create a new resource using **Docker Compose**
2. Point it at your repository and set the compose file to `docker-compose.coolify.yml`
3. Configure the required environment variables (see below)
4. Deploy

## Services Overview

| Service | Port | Memory | Description |
|---------|------|--------|-------------|
| `server` | 3001 (public) | 768 MB | API server + web app (the entry point) |
| `postgres` | 5432 (internal) | 512 MB | PostgreSQL with pgvector |
| `agent-computer` | 4100 (internal) | 1 GB | Shared browser for bot actions |
| `supervisor` | 4300 (internal) | 128 MB | Manages per-bot computer containers |
| `agent-langgraph` | 4201 (internal) | 256 MB | LangGraph bot (multi-provider) |
| `agent-bot` | 4200 (internal) | 256 MB | Proof-of-concept bot (OpenAI-compatible) |

**Total memory:** ~2.9 GB

## Environment Variables

### Auto-Generated by Coolify (SERVICE_URL_* / SERVICE_PASSWORD_* / SERVICE_BASE64_*)

These are automatically generated if not set. Coolify's magic variables ensure secure random values:

| Variable | Purpose |
|----------|---------|
| `SERVICE_URL_SERVER` | Full public URL (e.g., `https://openbot.example.com`) |
| `SERVICE_PASSWORD_POSTGRES` | Database password |
| `SERVICE_PASSWORD_COMPUTER` | Token for computer/browser access |
| `SERVICE_PASSWORD_SUPERVISOR` | Token for supervisor API |
| `SERVICE_PASSWORD_AGENT` | Token for managed bot endpoint |
| `SERVICE_PASSWORD_WORKER` | Worker shared secret for routines |
| `SERVICE_PASSWORD_TOOLTOKEN` | Token for tool callbacks |
| `SERVICE_BASE64_ENCRYPTION` | Key encryption key (32 bytes) |
| `SERVICE_BASE64_AUTHSECRET` | Better Auth session secret |

**Note:** Coolify also provides `SERVICE_FQDN_SERVER` (bare hostname without scheme), but OpenBot
requires full URLs with scheme for `BETTER_AUTH_URL`, so we use `SERVICE_URL_SERVER`.

### Required - Set These in Coolify

| Variable | Description | Example |
|----------|-------------|---------|
| `INTELLIGENCE_API_KEY` | CopilotKit Intelligence API key | `cpk_...` |

### Authentication Setup

OpenBot supports two authentication methods. Choose one:

#### Option 1: Email/Password (Recommended for Simple Setups)

This is the simplest option—no OAuth configuration required.

| Variable | Description | Example |
|----------|-------------|---------|
| `EMAIL_PASSWORD_AUTH` | Set to `true` to enable | `true` |
| `INITIAL_ADMIN_EMAIL` | Email for the initial admin account | `admin@example.com` |
| `INITIAL_ADMIN_PASSWORD` | Password for the initial admin (min 8 chars) | `secure-password-here` |

**Important notes:**
- Sign-up is disabled; only accounts created by administrators can sign in
- The initial admin is created automatically on first startup
- Additional users can be created through the admin API

#### Option 2: Google OAuth

For organizations that prefer OAuth-based sign-in.

| Variable | Description | Example |
|----------|-------------|---------|
| `EMAIL_PASSWORD_AUTH` | Set to `false` to disable email/password | `false` |
| `GOOGLE_OAUTH_CLIENT_ID` | Google OAuth client ID | `123...apps.googleusercontent.com` |
| `GOOGLE_OAUTH_CLIENT_SECRET` | Google OAuth client secret | `GOCSPX-...` |
| `INITIAL_ADMIN_EMAILS` | Admin email addresses (comma-separated) | `admin@example.com` |

**Google OAuth Setup:**

1. Go to [Google Cloud Console](https://console.cloud.google.com/apis/credentials)
2. Create a new OAuth 2.0 Client ID (Web application type)
3. Configure the following:
   - **Authorized JavaScript origins:** `https://your-domain.com`
   - **Authorized redirect URIs:** `https://your-domain.com/api/auth/callback/google`

For example, if your domain is `openbot.optimator.ai`:
- JavaScript origin: `https://openbot.optimator.ai`
- Redirect URI: `https://openbot.optimator.ai/api/auth/callback/google`

### Model Provider Configuration

OpenBot supports multiple model providers through OpenAI-compatible APIs:

#### DeepSeek (Recommended for cost-effective deployment)

```env
OPENAI_API_KEY=sk-your-deepseek-api-key
OPENAI_BASE_URL=https://api.deepseek.com
BOT_MODEL=deepseek-chat
```

#### OpenAI

```env
OPENAI_API_KEY=sk-your-openai-api-key
BOT_MODEL=gpt-4o
```

#### Anthropic

```env
BOT_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-your-key
BOT_MODEL=claude-sonnet-4-5
```

### Optional Configuration

| Variable | Default | Description |
|----------|---------|-------------|
| `OPENBOT_SINGLE_USER` | `false` | Single admin mode (refused on public domains) |
| `SIGNIN_ALLOWED_EMAIL_DOMAINS` | - | Restrict sign-in to specific domains (comma-separated) |
| `COMPUTER_MAX_BROWSERS` | `2` | Max concurrent browsers (memory tradeoff) |
| `COMPUTER_BROWSER_MODE` | `headless` | Browser mode (`headless` or `headed`) |

## Public Service Configuration

Coolify routes your domain to the `server` service on port 3001. The server handles:

- Web application (React frontend)
- API endpoints (`/api/*`)
- CopilotKit runtime
- Health check (`/health`)

### Domain Setup in Coolify

1. Add your domain to the `server` service
2. Coolify automatically:
   - Configures Traefik routing
   - Provisions TLS via Let's Encrypt
   - Sets `SERVICE_URL_SERVER` to the full URL (e.g., `https://openbot.example.com`)
   - Sets `SERVICE_FQDN_SERVER` to the bare hostname (not used by this compose)

## Network Architecture

```
Internet
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  Coolify / Traefik                                          │
│  (TLS termination, domain routing)                          │
└─────────────────────────────────────────────────────────────┘
    │
    ▼ Port 3001
┌─────────────────────────────────────────────────────────────┐
│  server (API + Web App)                                     │
│  └── Networks: default, data, computers                     │
└─────────────────────────────────────────────────────────────┘
    │                    │                    │
    ▼                    ▼                    ▼
┌──────────┐      ┌────────────┐      ┌──────────────┐
│ postgres │      │ supervisor │      │ agent-bots   │
│ (data)   │      │ (default)  │      │ (default)    │
└──────────┘      └────────────┘      └──────────────┘
                       │
                       ▼ spawns
              ┌────────────────┐
              │ agent-computer │
              │ (computers)    │
              └────────────────┘
```

### Network Isolation

- **data**: Database only (isolated from bot computers for security)
- **default**: Service-to-service communication
- **computers**: Bot computers reaching the server

## Memory Tuning

The default configuration targets a VPS with 8 GB RAM shared with other applications:

| If you have... | Adjust... |
|----------------|-----------|
| More RAM | Increase `agent-computer` mem_limit for more browsers |
| Less RAM | Reduce `COMPUTER_MAX_BROWSERS` to 1 |
| Many bots | The supervisor spawns per-bot containers from `agent-computer` image |

### Per-Bot Computer Memory

The supervisor creates containers for each bot. These inherit settings from environment variables.
With `COMPUTER_MAX_BROWSERS=2`, each bot can have up to 2 concurrent browser sessions, each using
~200-500 MB.

## Health Checks

All services expose health endpoints:

```bash
# Server (public)
curl https://your-domain.com/health

# Internal services (from within Coolify SSH or exec)
curl http://agent-computer:4100/health
curl http://supervisor:4300/health
curl http://agent-langgraph:4201/health
curl http://agent-bot:4200/health
```

## Upgrading

1. Pull the latest code in Coolify
2. Redeploy - migrations run automatically before the server starts

## Troubleshooting

### Stack starts but bots don't work

Check that `INTELLIGENCE_API_KEY` is set. The server refuses to start without valid Intelligence
credentials.

### "Key encryption key" errors

Ensure `SERVICE_BASE64_ENCRYPTION` is set. Coolify should auto-generate this, but you can manually
set it:

```bash
openssl rand -base64 32
```

### Browser actions fail

1. Check `agent-computer` logs for errors
2. Verify `COMPUTER_TOKEN` matches between server and agent-computer
3. Ensure the `computers` network exists

### Per-bot computers not starting

1. Verify supervisor has Docker socket access
2. Check that `COMPUTER_NETWORK` matches the actual network name
3. Coolify prefixes network names with project name, e.g., `myproject_computers`

### Out of memory

1. Reduce `COMPUTER_MAX_BROWSERS`
2. Lower `mem_limit` values (at the cost of stability)
3. Consider upgrading VPS RAM

## Production Checklist

- [ ] Set `OPENBOT_SINGLE_USER=false`
- [ ] Configure authentication (email/password OR OAuth):
  - Email/password: Set `EMAIL_PASSWORD_AUTH=true`, `INITIAL_ADMIN_EMAIL`, `INITIAL_ADMIN_PASSWORD`
  - OAuth: Set `EMAIL_PASSWORD_AUTH=false`, configure OAuth provider, set `INITIAL_ADMIN_EMAILS`
- [ ] Configure a model provider (OPENAI_API_KEY or alternatives)
- [ ] Verify all health endpoints respond
- [ ] Test browser actions work end-to-end
- [ ] Set up Coolify backups for postgres-data volume

## What's Not Included

**SPIRE (workload identity)**: Optional attestation service. Not required for basic operation.

**agent-harness**: Framework-picker service. Use `agent-langgraph` which supports multiple providers.

**Routines worker**: Scheduled tasks require a separate worker process. For now, routines won't fire
automatically. A future update may add a worker service.
